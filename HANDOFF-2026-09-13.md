## 2. The two bugs that cost the session

### SkinMaterial returned before the look settings

```csharp
if (alreadyOurs && SkinnedMaterials.Contains(mat.GetInstanceID()))
    return;          // ApplyWetness and ApplyGroundFade were BELOW this
```

On a world reload the material already held our texture, so the early return fired and
`Wetness`, `Reflections` and the rest were never written. **They only applied on a full
relaunch, while the settings screen implied they were live.** Hours were spent changing
settings that could not take effect, and three separate diagnoses were built on top of
readings that were never applied.

Fixed: materials are tracked in `Owned` as **references** (an instance id is not a handle),
and `BloodSkin.RefreshLookSettings()` runs from `ApplyToScene` at every world load.

Still needs a relaunch, and this is worth knowing before debugging anything:

- `GroundOpacity` — baked into texture pixels in `Solidify` at load
- `GroundNormalMap` off → on — the normal map was never loaded at startup

### splat_decal_blend draws at half brightness

Read from bundle `c4210710`:

```
splat_decal_blend    _Color (0.502, 0.502, 0.502)   _TintColor (1, 1, 1, 0.5)
seeker_blood_splat   _Color (0.557, ...)
SeekerQueen_decals   _Color (0.708, ...)
blood_splat          _Color (1, 1, 1)
```

Vanilla's reddish `brains` texture carried enough colour to survive the halving. This mod's
greyscale artwork relies entirely on the creature's `startColor`, so half of it was thrown
away. `_Color` is now raised to white in `ApplyWetness`.

**`_TintColor` is deliberately NOT touched.** Its 0.5 alpha may be a legacy-neutral value
that the shader doubles internally; forcing it to 1 could over-brighten, and the shader is
custom so this cannot be read from the bundle.

## 3. Why ground blood looked wrong, in the order it was diagnosed

Five wrong theories before the right ones. All five measured plausibly offline and failed in
game. The lesson is in §7.

1. ~~Premultiplied vs straight alpha~~ — real, but not the cause. Vanilla's `brains` measures
   flat 255 at solid pixels (straight alpha); ours is premultiplied. Whitening the RGB was
   tried and made ground blood render as a pale blue-white network. **Reverted.** The
   interaction with the normal map and lighting is unresolved.
2. ~~Normal map written to the wrong slot~~ — `SetNormal` wrote `_BumpMap` and enabled
   `_NORMALMAP` on every blood material. Correct for `Particles/Standard Surface2`, wrong to
   apply to `Custom/ParticleDecal`. Narrowed to `_NormalTex` where it exists. Not the cause.
3. ~~Gradient start colours being skipped~~ — dead. 508 blood systems measured: **302 range,
   206 single, 0 gradient.**
4. ~~Specular~~ — pixel measurement showed hue 1–28°, i.e. red through orange, never magenta.
5. ~~HDVT's texture tinting it~~ — all three competing textures measure neutral `G/R 1.00`.

**The actual causes**, both confirmed by measuring screenshots:

- **`Reflections` mirroring the sky.** The mark's colour tracked the weather — blue under a
  clear sky, grey under cloud. Default is now `false`.
- **Brightness, not hue.** The version the owner liked measured `val 0.48, sat 0.43`; the
  version called "pink" measured `val 0.83, sat 0.54` — *more* saturated, just far brighter.
  Bright desaturated red is what pink is.

### GroundOpacity is the real brightness control

These decals blend, so overlaps stack toward solid:

```
alpha 0.85:  1 layer 0.85   2 layers 0.98   3 layers 1.00
alpha 0.55:  1 layer 0.55   2 layers 0.80   3 layers 0.91
```

At the high end two marks are opaque and the colour underneath stops mattering — **halving
`BloodColor` moved the on-screen result by 9%.** Chasing colour while opacity is high is
wasted effort.

Range widened to **0.2–3.0**, and its guard fixed: `mul <= 1.001f` silently ignored every
value below 1, which would have shipped a slider whose lower half did nothing.

multiplies it up. Judge it in game.

## 5. Open, with evidence

### Hits rarely mark the ground

`GroundBlood 0.3` multiplies the authored decal chance. Greydwarf's hit decal is authored
`m_chance = 100`, so **30% of hits mark**. Noticeable on elites because they take more hits.
Affects every creature identically — not a bug.

```
GroundBlood   100% chance becomes
   0.3  (shipped Normal)   30%
   0.6                     60%
   1.0  (vanilla)         100%
```

It also scales size, lifetime and the decal cap. 0.6–0.75 was suggested; **the owner has not
decided.** If they land elsewhere, change `BloodPreset.For(Normal).Ground` before uploading.

### Some marks shrink when you zoom out

Measured across mip levels, visible radius at alpha > 0.25:

```
spray  (39% dense)   46% -> 31%   lost 32%
mist   (27% dense)   50% -> 19%   lost 62%
impact (15% dense)   47% -> 19%   lost 60%
```

`mist` and `impact` are sparse fine structure that averages toward transparent when sampled
small, so they collapse to their cores. `spray` is dense enough to hold. Since large marks
coin-flip between `spray` and `mist`, roughly half shrink and half do not, which reads as
arbitrary.

This answers `HANDOFF.md` §7 question 4 — the coin flip reads as noise, not variety.

**Owner decided to leave it as is** ("I don't want to break anything"). Options if revisited:
drop the coin flip so every large mark uses `spray`, or thicken the other two textures toward
39% density. The first is one line in `AssignGroundVariant`.

### Lighting mods on this install

`BadgersShadingOverhaul`, `BadgersValheimSkies` and `HDValheimTextures` are installed and
staying. HDVT overwrites `splat_decal_blend._MainTex` with `brains-7264202d` after world
load; the mod writes ours back on the next decal — visible in the log, working as designed.

`GroundLighting = false` exists as the escape hatch: it sets `_LightingEnabled = 0`, taking
ground decals out of the lighting path entirely. Default is **on**, because unlit loses the
wet look and the owner wants blood to read as liquid.

## 6. Ground blood reference data

Read from bundle `c4210710` with AssetsTools.NET. Tooling in the session scratchpad; the
outputs are on the Desktop in `Valheim Blood By Creature` and `Greydwarf blood texture`.

- **101 blood effects, 216 ground-blood systems, all covered by the mod.** The only
  uncovered ground material is `puke` (4 effects), excluded on purpose.
- **Only two ground textures exist in the whole game**: `brains` 64×64 (100 effects) and
  `leaf_low` **8×8** (59 effects). All variety is colour, size and chance — never shape.
- **85 distinct ground marks; 27 are shared by more than one effect.** The largest group is
  51 effects sharing one red `#ED0707` death splat.
- `blood_splat2` has `maxParticles = 0` on all 49 slots — **never drawn anywhere**. Ignore it,
  including its alarming pure-white neck-death entry.
- Greydwarf ground blood is **yellow by design**: hit `rgb(0.82, 0.80, 0.10)`, death
  `rgb(0.85, 0.72, 0.00)`. `DeepenRed`'s `IsRedBlood` test excludes it (green 0.80 > r×0.4),
  so `BloodTint` and `BloodColor` are **red-only levers** and cannot disturb yellow.

### The graph file is easy to misread

`EffectGraph` logs the ParticleDecal's **own transform**, which is the *colliding spray*, not
the system that draws the mark. A node named `vfx_BloodHit_decals` is a spray. The real mark
is the node the graph labels `DECAL`. Misreading this produced a confidently wrong answer
about greydwarf blood being dark olive; it is bright yellow.

## 7. Process lessons

- **Read the live config before theorising.** `Reflections = true` sat in the config while
  three diagnoses were built around textures and shaders. The config read should have been
  the first move, not the fourth.
- **Verify a setting actually changed.** Twice a test "ran" against a value that had not
  taken — once because BepInEx wrote its in-memory copy back over a file edit, once because
  the early return meant it could not apply. Both times the conclusion drawn was wrong.
- **Measure the output, not just the input.** Predicting from albedo and blend maths failed
  repeatedly. Sampling the screenshot's pixels settled hue vs saturation vs brightness in one
  step and showed the problem was never hue.
- **Isolate before tuning.** 57 mods were installed, two of which reshape lighting, and this
  was never tested with them off. "Assume they cause it and work around it" was the right
  call once it was finally asked.
- Python heredocs kept failing on this repo's CRLF line endings — `io.open(..., newline='')`
  will not match patterns written with `\n`. Use the Edit tool for C# edits.
